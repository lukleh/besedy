## Identifiers and Terminology

| Term | Definition |
|------|------------|
| **Audio hash** | SHA-256 of decoded signed 16-bit PCM audio (`pcm-s16le-16000hz-mono-sha256-v1`, 64 hex chars). Ignores container metadata (ID3 tags, cover art) so identical decoded audio content yields the same hash across files. Primary recording identifier everywhere. |
| **Speaker ID scope** | Speaker identifiers (e.g. `SPEAKER_01`) are unique only within a single audio file. The same ID in different files refers to different speakers. |
| **Segment** | Continuous speech region with text, timestamps, and confidence. |
| **Word** | Individual word with precise timing and confidence score. |
| **Pipeline naming** | Format: `model[strategy]@vad[@align][@lang-<language>]`. Model = ASR engine. Optional strategy = NeMo decode mode (`[greedy]`/`[beam]`). VAD = voice activity detector. Align = alignment model when applicable. Language is omitted only for the legacy-compatible Czech (`cs`) path; automatic detection uses `@lang-auto`. |

## Backend Identifiers

Canonical workflow IDs used in CLI commands, directory names, and
`meta.backend` inside transcript JSON.

| Backend | Workflow ID | Directory Pattern |
|---------|-------------|-------------------|
| Canary-NeMo | `canary-nemo` | `canary-nemo/nvidia_canary-1b-v2[greedy]@frame_vad_multilingual_marblenet_v2_0` |
| Canary-NeMo (beam) | `canary-nemo-beam` | `canary-nemo/nvidia_canary-1b-v2[beam]@...` |
| Faster-Whisper | `faster-whisper` | `faster-whisper/large-v3@silero_vad_v6@lang-auto` |
| WhisperX | `whisperx` | `whisperx/large-v3@silero@lang-auto` |
| Qwen3-ASR | `qwen3-asr` | `qwen3-asr/<model>@<vad>[@<align>]@lang-auto` |
| Pyannote Diarization | `pyannote` | `speaker_diarization/pyannote_speaker-diarization-community-1` |

**Output-component pattern:**
`{model_name}[{strategy}]@{vad_model}[@{align_model}][@lang-{language}]`.
The language suffix prevents auto-detected or explicitly non-Czech runs from
reusing transcripts created under the old forced-Czech default. Czech
(`language = "cs"`, which is also the default when the key is omitted)
deliberately retains the historical path without a suffix.

Source of truth: `besedy/lib/backend_ids.py`

## Storage Layout

### Catalog Files

| Path | Contents |
|------|----------|
| `audio_catalog_<timestamp>.csv` | Audio hash, `Hash Algorithm`, ffprobe metadata, `added_at` (ISO 8601). Created by `catalog create`. |
| `audio_catalog_<timestamp>_loudness.csv` | Loudness/volume analysis. Created by `catalog loudness`. Required for `stage-audio`. |
| `audio_catalog_<timestamp>_duplicates.csv` | Duplicate-file report (same audio hash). Created by `catalog create` when duplicates found. |
| `audio_catalog_<timestamp>_joined.csv` | Joined-audio manifest (source parts + output hash/path). Created by `catalog join`. |
| `audio_catalog.csv` | Symlink to latest basic catalog. Auto-updated by `catalog create`. |
| `audio_catalog_loudness.csv` | Symlink to latest loudness catalog. Auto-updated by `catalog loudness`. |
| `audio_catalog_duplicates.csv` | Symlink to latest duplicates report. |
| `audio_catalog_joined.csv` | Symlink to latest joined manifest. |
| `sample.csv` | Subset manifest for quick testing. |

### Transcript and Diarization Files

| Path | Contents |
|------|----------|
| `transcripts/<backend>/<output-component>/<audio_hash>/transcript.json` | Canonical transcript (all backends share the same schema). |
| `transcripts/<backend>/<output-component>/<audio_hash>/transcript.{txt,srt,vtt}` | Sidecar files: plain text, SRT subtitles, WebVTT subtitles. Generated by `just catalog export-transcripts`. |
| `transcripts/speaker_diarization/<model>/<audio_hash>/speakers.json` | Pyannote diarization segments. |
| `transcripts/speaker_embeddings/pyannote-embedding/file/<audio_hash>/embeddings.json` | Per-speaker embedding vectors (internal clustering cache). |
| `speaker_clusters_<timestamp>/clusters_pyannote.json` | Cross-file speaker cluster assignments. Symlinked from `speaker_clusters/`. |

`<audio_hash>` in persisted artifact paths is the complete 64-character value.
Commands may accept or display an unambiguous prefix, but writers do not create
truncated hash directories.

### Staging and Logs

| Path | Contents |
|------|----------|
| `<staging-dir>/{hash}.wav` | Normalized WAV files for transcription. Created by `just catalog stage-audio`. |
| `logs/ffmpeg/ffmpeg_stage_*.log` | Source-audio prep logs (resampling, trimming). |

### Processing Pipeline

`catalog run-pipeline` orchestrates source audio in the catalog CSV -->
loudness analysis --> 16 kHz mono staging --> transcription and downstream
artifacts. The `catalog loudness` and `catalog stage-audio` names above are the
lower-level handlers responsible for those intermediate files.

## Transcript Schema

**File:** `transcript.json`
**Location:** `transcripts/<backend>/<output-component>/<audio_hash>/transcript.json`
**JSON Schema:** `docs/schemas/transcript.schema.json`
**Validator:** `besedy/lib/validation/schema.py`

All transcription backends write the same canonical format. The `meta` block
carries backend-specific provenance; the `segments` array is structurally
identical across backends.

### Top-Level Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `meta` | object | No | Backend/model provenance, generation parameters, summary stats. |
| `language` | string | No | ISO 639-1 language code (e.g. `"cs"`). May appear at top level or inside `meta`. |
| `duration` | number | No | Total audio duration in seconds. May appear at top level or inside `meta`. |
| `segments` | array | **Yes** | Array of transcript segments. |

### meta Object

| Field | Type | Description |
|-------|------|-------------|
| `backend` | string | Workflow ID matching directory name (`canary-nemo`, `faster-whisper`, `whisperx`, `qwen3-asr`). |
| `model` | string | Model identifier (e.g. `nvidia/canary-1b-v2`, `large-v3`). |
| `audio_filepath` | string | Path to source audio at transcription time. |
| `duration` | number | Total audio duration in seconds. |
| `num_segments` | number | Segment count. |
| `num_words` | number | Total word count. |
| `transcript_text` | string | Full concatenated transcript text. |
| `generation_params` | object | Backend-specific parameters (VAD config, compute settings, decoding options). |

### Segment Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | number | No | Segment index (0-based). |
| `text` | string | **Yes** | Transcribed text for this segment. |
| `start` | number | **Yes** | Start time in seconds (float). |
| `end` | number | **Yes** | End time in seconds (float). |
| `confidence` | number | No | Average confidence (0.0--1.0). Calibration differs by backend. |
| `words` | array | No | Word-level timestamps (when available). |
| `speaker` | string | No | Speaker ID (when diarization has been merged). |

### Word Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `word` | string | **Yes** | Individual word (may include punctuation). |
| `start` | number | **Yes** | Word start time in seconds. |
| `end` | number | **Yes** | Word end time in seconds. |
| `confidence` | number | No | Word confidence (0.0--1.0). |

### Example (minimal)

```json
{
  "language": "cs",
  "duration": 3245.67,
  "segments": [
    {
      "id": 0,
      "text": "Dobry den, vitejte.",
      "start": 0.0,
      "end": 2.5,
      "words": [
        { "word": "Dobry", "start": 0.0, "end": 0.8, "confidence": 0.95 },
        { "word": "den,", "start": 0.9, "end": 1.3, "confidence": 0.92 },
        { "word": "vitejte.", "start": 1.5, "end": 2.5, "confidence": 0.88 }
      ]
    },
    {
      "id": 1,
      "text": "Dnes budeme mluvit o...",
      "start": 3.0,
      "end": 5.2
    }
  ]
}
```

### Backend-Specific Notes

**Canary-NeMo:** Uses Frame VAD (MarbleNet) for segmentation. `generation_params`
includes VAD tuning (chunk length, silence thresholds, padding). Confidence
calibration ~0.93 average.

**Faster-Whisper:** Silero VAD, CUDA float16 inference. `generation_params`
includes `duration_after_vad`, full `transcription_options` (beam size, repetition
penalty, temperature schedule). Confidence calibration ~0.88 average.

**WhisperX:** Silero VAD + alignment model (`comodoro/wav2vec2-xls-r-300m-cs-250`)
for stable word timings. Produces raw output first (`_raw_whisperx` when
`--keep-raw` is enabled), then auto-converts to canonical format.

> **Legacy note:** Existing whisper.cpp transcripts are retained as historical
> data, but the active pipeline uses WhisperX. The loader preserves encoding
> fallback for those older files.

## Diarization Schema

**File:** `speakers.json`
**Location:** `transcripts/speaker_diarization/pyannote_speaker-diarization-community-1/<audio_hash>/speakers.json`

Pyannote is the sole active diarization backend.

### Top-Level Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `audio_file` | string | No | Path to source audio at diarization time. |
| `model` | string | No | Diarization model identifier. |
| `num_speakers` | number | **Yes** | Total number of detected speakers. |
| `segments` | array | **Yes** | Array of speaker segments. |

### Segment Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `speaker` | string | **Yes** | Speaker identifier (e.g. `SPEAKER_00`). |
| `start` | number | **Yes** | Segment start time in seconds. |
| `end` | number | **Yes** | Segment end time in seconds. |

### Example

```json
{
  "num_speakers": 2,
  "segments": [
    { "speaker": "SPEAKER_00", "start": 0.0, "end": 15.3 },
    { "speaker": "SPEAKER_01", "start": 15.5, "end": 28.7 },
    { "speaker": "SPEAKER_00", "start": 29.0, "end": 45.2 }
  ]
}
```

### Notes

- Speaker IDs are scoped to a single audio file (not globally unique).
- Segments may overlap when speakers talk over each other.
- The `SPEAKER_XX` format is conventional but not enforced.
- Fine-grained segmentation (~3.3 s average per segment).
- Typically 4--10 speakers per recording.

## Speaker Embeddings

**File:** `embeddings.json`
**Location:** `transcripts/speaker_embeddings/pyannote-embedding/file/<audio_hash>/embeddings.json`

Internal intermediate artifact for speaker clustering. Not intended for direct
analysis, similarity queries, or speaker verification.

**Pipeline:** Diarization --> Embeddings (cached) --> Clustering

### Schema

| Field | Type | Description |
|-------|------|-------------|
| `metadata.version` | number | Schema version. |
| `metadata.mode` | string | Processing mode (e.g. `"file"`). |
| `metadata.model_name` | string | Embedding model identifier. |
| `metadata.min_duration` | number | Minimum segment duration in seconds. |
| `metadata.audio_file` | string | Source audio path. |
| `metadata.segments_checksum` | string | SHA-1 checksum of input segments. |
| `metadata.updated_at` | string | ISO 8601 timestamp. |
| `speakers.<ID>.vector` | array | 512-dimensional embedding vector (floats). |
| `speakers.<ID>.duration` | number | Total speaking time in seconds. |
| `speakers.<ID>.num_segments` | number | Number of segments for this speaker. |

## Speaker Clusters

**File:** `clusters_pyannote.json`
**Location:** `speaker_clusters_<timestamp>/clusters_pyannote.json`
(symlink: `speaker_clusters/clusters_pyannote.json`)

Groups similar speakers across different recordings using cosine similarity on
Pyannote embeddings.

### Available Variants

| File | Distance Threshold |
|------|--------------------|
| `clusters_pyannote-embedding.json` | 0.35 (default) |
| `clusters_pyannote-embedding_d035.json` | 0.35 |
| `clusters_pyannote-embedding_d040.json` | 0.40 |
| `clusters_pyannote-embedding_d045.json` | 0.45 |
| `clusters_pyannote-embedding_d050.json` | 0.50 |

### Schema

**metadata:**

| Field | Type | Description |
|-------|------|-------------|
| `cluster_distance` | number | Clustering distance threshold. |
| `num_files` | number | Number of audio hashes processed. |
| `num_speakers` | number | Total (file_id, speaker) entries. |
| `num_clusters` | number | Multi-file + singleton clusters. |
| `num_multi_file_clusters` | number | Clusters spanning multiple files. |
| `num_singleton_clusters` | number | Single-member clusters. |
| `timestamp` | string | ISO 8601. |

**speakers array:** One entry per (file_id, speaker) pair.

| Field | Type | Description |
|-------|------|-------------|
| `index` | number | Global speaker index. |
| `file_id` | string | Audio hash. |
| `speaker` | string | Speaker ID within that file. |

**clusters array:**

| Field | Type | Description |
|-------|------|-------------|
| `cluster_id` | number | Cluster identifier. |
| `size` | number | Number of members. |
| `num_files` | number | Number of distinct audio files in cluster. |
| `members` | array | Array of `{index, file_id, speaker}` objects. |
| `distances` | object | `{min, avg, max}` pairwise distances within cluster. |

**Optional large arrays:** `distance_matrix` (pairwise distances) and
`all_pairs` (detailed pair records with `cosine_distance` and
`similarity_percent`). Both can be very large.

## Directory Structure and Discovery

### Full Tree

```
transcripts/
  canary-nemo/
    nvidia_canary-1b-v2[greedy]@frame_vad_multilingual_marblenet_v2_0/
      {audio_hash}/
        transcript.json
  faster-whisper/
    large-v3@silero_vad_v6/
      {audio_hash}/
        transcript.json
        transcript.txt          # optional sidecar
        transcript.srt          # optional sidecar
        transcript.vtt          # optional sidecar
  whisperx/
    large-v3@silero@comodoro_wav2vec2-xls-r-300m-cs-250/
      {audio_hash}/
        transcript.json
  speaker_diarization/
    pyannote_speaker-diarization-community-1/
      {audio_hash}/
        speakers.json
  speaker_embeddings/
    pyannote-embedding/
      file/
        {audio_hash}/
          embeddings.json

speaker_clusters_<timestamp>/
  clusters_pyannote.json
  clusters_pyannote-embedding.json
  clusters_pyannote-embedding_d035.json
  clusters_pyannote-embedding_d040.json
  clusters_pyannote-embedding_d045.json
  clusters_pyannote-embedding_d050.json
```

### Audio Hash Format

64 hexadecimal characters (SHA-256).
Example: `0f2fa31aad030970207da2b59a89a49a0abb6172ea486528369ebf997291cc91`

The catalog's `Hash Algorithm` value is
`pcm-s16le-16000hz-mono-sha256-v1`. A file that ffmpeg cannot decode is
reported as an ingest error and omitted from the catalog; Besedy never
substitutes a different identity algorithm for the canonical `Hash` column.

Catalogs without `Hash Algorithm` are unsupported and cannot be appended to or
merged. Recreate them from source audio so every identity is computed under the
canonical contract.

### Hash Sidecars

Canonical sidecars use `<source>.audiohash`. Their first line is
formatted as `<hash><two spaces><filename>`, followed by the audio identity
contract and an exact source-file checksum used only for cache validation:

```text
0f2fa31aad030970207da2b59a89a49a0abb6172ea486528369ebf997291cc91  recording.mp3
# besedy-audio-hash-algorithm: pcm-s16le-16000hz-mono-sha256-v1
# besedy-source-file-sha256: 4ebc2f98437c9b4a49f1b7d036a4f49c08b8604e494af43373fda0627d791e66
```

Untyped `.audiohash` files are recomputed once because the identity contract
cannot be inferred from a 64-character value alone. The source-file checksum
is integrity metadata for deciding whether a typed sidecar still describes the
same source bytes; it is never a recording identifier or catalog join key.

### Discovery Rules

1. The web app uses the **first** model directory found under each backend.
2. Diarization backends are matched by **prefix** (`pyannote_*`).
3. If no model directory exists under a backend, that backend is unavailable.
4. Audio hash directories are immediate children of the model directory.

### Sidecar Files

| Format | Extension | Description |
|--------|-----------|-------------|
| Plain text | `.txt` | Raw transcript text, one segment per line. |
| SRT | `.srt` | SubRip subtitle format with timestamps. |
| VTT | `.vtt` | WebVTT subtitle format with timestamps. |

Generated by `just catalog export-transcripts`.

## Relationships and Join Keys

```
Audio File (SHA-256 hash)
  |
  +-- Transcript (per backend: canary-nemo, faster-whisper, whisperx, qwen3-asr)
  |
  +-- Speaker Diarization (Pyannote only)
        +-- Speaker Embeddings (internal clustering cache)
              +-- Speaker Clusters (multiple distance thresholds)
```

**Transcripts <--> Diarization:** Join on audio hash + time overlap.

```
transcript_segment.audio_hash == diarization.audio_hash
AND transcript_word.start >= diarization_segment.start
AND transcript_word.end   <= diarization_segment.end
```

**Diarization <--> Clusters:** Join on `(file_id, speaker)` in cluster members
matching `(audio_hash, speaker)` in diarization segments.

**Embeddings** are an intermediate cache between diarization and clustering.
For analysis, use diarization data directly for speaker timing and cluster data
for cross-recording speaker identification.

## Metrics Reference

| Term | Definition | Typical Values |
|------|------------|----------------|
| **Confidence** | ASR model certainty about a word/segment (0--1). Calibration varies by model. | NeMo ~0.93, Whisper ~0.88 |
| **Z-Score** | Normalized confidence (standard deviations from model mean). Enables fair cross-model comparison. | 0 = mean, +/-2 = unusual |
| **Jaccard Similarity** | Set-based similarity: \|intersection\| / \|union\| of word sets. Used for short section comparison. | 0.0 = no overlap, 1.0 = identical |
